# 大肥鱼 QQ 机器人 · 本机部署

基于 [SAKURAfan1023/dafeiyu-bot](https://github.com/SAKURAfan1023/dafeiyu-bot)，上游版本 `cc8170396bc68266077204576f8469e414b5c44c`。原项目接 DeepSeek，这里换成本机模型：本机 Codex（复用 ChatGPT 登录）、本机官方 Claude Code，或自己的云端 API，在控制台里切换。QQ 引擎、人格、表情、会话记忆和原面板保留。

2026-11-03 起整个机器人直接跑在 Windows 上，不再用 WSL（用户：“其实我不想用任何wsl了”“wsl太占性能了”）：引擎从 Swift 改写成 Node（`engine/`），QQ 由 Windows 上的 SnowLuma 接管，详见下面「在 Windows 上运行」。`upstream/` 里原作者的 Swift 引擎和 WSL 脚本留作对照和回滚，不再使用。

## 日常使用

- **启动**：双击 `Dafeiyu.exe`（或 `Start.cmd`）。它在后台拉起网关，网关再拉起 SnowLuma 和引擎，不弹任何终端窗口，托盘里出现大肥鱼图标，然后打开控制台。
- **托盘菜单**：打开控制台、暂停/开始回复、重启机器人、重启 SnowLuma、开机自启、停止大肥鱼并退出、只退出托盘（机器人继续运行）。双击图标也会打开控制台。
- **开机自启**：托盘菜单或控制台「设置」里开关，写入当前用户的 `HKCU\…\Run\Dafeiyu`，默认关闭。
- **控制台**：`http://127.0.0.1:18191/console/`，只监听本机。第一次从启动器或 `Console.cmd` 打开时设置密码，之后用密码登录；密码在「设置」里随时改，改完其他浏览器需要重新登录。
- **远程打开（frp 等隧道）**：设置过密码后，用隧道的域名访问 `/console/` 也可以，必须登录；直接打开 `/bot/` 或 NapCat 页面会先跳到登录。通过隧道只能用控制台和它内嵌的页面，模型接口 `/v1/*` 和启动器令牌只认本机地址。连续输错 5 次密码锁 30 秒，再错锁定时间翻倍（最长 1 小时）。隧道是明文 HTTP 时密码和登录 Cookie 会明文过网，建议在 frp 上配 HTTPS。
- **QQ 掉线需要重新登录时**：在机器人那个 QQ 窗口里重新登录。登上后网关自动核对账号、重连，并恢复到你上次的回复状态（在回复就继续回复，暂停就保持暂停）。
- `Stop.cmd` 停止网关、引擎和 SnowLuma（QQ 窗口不动）；`Status.cmd` 查看各进程、内存和状态。日志在 `.runtime/logs/`（`gateway.log`、`engine.log`、`snowluma.log`，超过 20 MB 换新）。

## 在 Windows 上运行（2026-11-03 起）

原来是 WSL 里的 Docker 跑 NapCat（一个 Linux 版 QQ）、systemd 管 Swift 引擎和 Node 网关，WSL 常驻约 2 GB。现在全部是 Windows 进程：

- **网关**（`node bridge/main.mjs`，配置 `.runtime/bridge-windows.json`，Windows 路径；WSL 的 `bridge.json` 保留不动）：模型接口和控制台照旧，另外由 `bridge/qq-host.mjs` 接过原来 systemd 和 `scripts/supervisor.py` 的活——拉起 SnowLuma 和引擎、引擎退出 5 秒后重启、QQ 登上后核对账号再连、按上次的选择恢复回复。Windows 不会随父进程结束子进程，所以引擎和 SnowLuma 的 pid 记在 `.runtime/engine.pid`、`snowluma.pid`，新网关先结束旧引擎再起新的。
- **引擎**（`node engine/main.mjs`）：`upstream/Sources` 逐文件改写成 Node，类型名、字段名和存盘格式与 Swift 版一致（日期仍按 Swift 的“2001 年起的秒数”存），WSL 里的 `qq-state.json` 和表情库原样搬到 `.runtime/engine/` 就能用；控制接口（`/api/status`、`/api/action`、`X-QQ-Control`）不变，控制台照常代理。原来的 Swift 测试都改成了 `tests/engine-*.test.mjs`，`npm test` 一起跑。
- **QQ = SnowLuma**（`D:\Dev\Projects\SnowLuma`，v2.3.4）：把钩子挂进 Windows 版官方 QQ.exe，提供 NapCat 兼容的 OneBot 接口（我们用到的动作它都支持）。只给机器人号用：OneBot 配置只写在 `config/onebot_<机器人QQ号>.json` 里（全局的 `onebot.json` 是空的），全部只监听 127.0.0.1；它的自动挂载（会挂进这台电脑上**所有** QQ.exe，包括主人自己的 QQ）关掉，由网关在 SnowLuma 的进程列表里找登录着机器人号的那个 QQ 进程，只给它挂。重启 SnowLuma 不会让 QQ 下线。
- **登录**：在这台电脑上另开一个 QQ 窗口登录机器人的号（主人自己的 QQ 照常用），别的都是自动的。SnowLuma 的管理密码由机器人自己管（11-03 主人不想填，且把密码贴进了聊天）：没有时网关生成一个随机密码，按 SnowLuma 自己的格式（scrypt，参数见它的 `packages/core/src/webui/auth.ts`）写进 `D:\Dev\Projects\SnowLuma\config\webui.json`，自己存在 `.runtime/snowluma.json`，谁都不用知道。机器人号也记在这个文件里（`account`）。
- **控制台里的 SnowLuma**（11-03：“我希望把控制台也做嵌入处理”）：「QQ 登录」页上面一行是机器人 QQ 的状态，下面直接嵌着 SnowLuma 自己的管理页，已经登录好。SnowLuma 的页面挂在根路径、又禁止被嵌入，所以网关另开一个本机端口 18192（`bridge/snowluma-proxy.mjs`）转发它：去掉禁止嵌入的头、只许控制台嵌、每个请求换成机器人自己的 SnowLuma 会话；只有登录了控制台的人进得去（控制台的 Cookie 不分端口）。这个端口只在本机，远程打开控制台时这里只显示状态。
- **不弹窗口**：SnowLuma 由网关在后台隐藏启动，挂了会自动拉起（QQ 不会因此下线）；有人手动用 `start-dafeiyu.cmd` 开了带黑框的那个，网关接管时会把它连同窗口一起关掉。
- **其他换成 Windows 的部分**：自建工具的沙箱只靠 Node 的 `--permission`（Node 25 起它也禁网络，Windows 上没有 `unshare`）；语音直接把 WAV 交给 SnowLuma，由它自己转 SILK（不再要 pilk）；B 站截帧用 `D:\Dev\Tools\ffmpeg`（gyan.dev 的 essentials 构建，`bridge-windows.json` 的 `ffmpeg`）；图片处理仍是 `upstream/Resources/Linux/image-helper.py`，用 Windows 的 Python + Pillow 跑（`resource` 模块在 Windows 上没有，所以没有内存上限，30 秒超时和 20 MB 输出上限照旧）；超级模式直接调 `cmd.exe`。
- **回滚到 WSL**：停掉 Windows 网关（`Stop.cmd`），在 WSL 里 `systemctl --user start dafeiyu-codex.service dafeiyu-bot.service` 并启动 NapCat 容器；那边的状态停在切换那一刻。

## 2026-11-03 拆掉的限制和新人设

用户：“把乱七八糟的过度防护全拆了”。拆掉的：
- 发消息：没有每天、每个会话、每小时的条数上限，不再“最近发得多就隔得更久”、不加随机等待；只剩两条之间隔几秒（默认 1 秒）和同一会话的冷却（默认 0）。控制台「节奏与额度」里只剩这两项。
- 模型调用不限次数（只计数）；助手类调用的输出上限 500 → 4000 tokens。
- 贴表情、戳一戳、点赞的每小时次数，定时提醒和笔记本的条数，找主人一天三次的限制，插画每会话每天 20 张，表情包 24 小时内不重发。
- 指挥一轮最多 20 步、每步 6 个工具 → 60 步、24 个；网关每次回复只认 2 个工具调用 → 16 个；同时回复的会话 2 个 → 8 个；画图不排队，同时画。
- 单条回复不截断到 60 字（上限 2000），一条回复最多拆成 10 条消息（原来 3 条）。
- 复读/机器人互聊保护关闭；超过 10 分钟的消息不再丢（放宽到 1 小时，只为重启后不回很久以前的话）。
- 文字里出现 “[CQ:”“file://”“base64://” 不再整条不发（文字按纯文本段发，没有影响）；画图描述和搜索词里带网址、长数字不再拒。
- 合规提示从一大段（“不评论、不调侃、不转述……谣言……历史争议”）缩成一句：不聊国家领导人和时政敏感话题，不写色情和性暗示。画图只拒露骨色情和未成年人性化，不再因“含义模糊”拒、不再要求群里点名大肥鱼才画，衣服按请求来。看图助手认得出的角色、名人直接说。

留着的（挡外人、护账号和电脑）：拉黑/禁言/设精华/改群性格要管理员，超级模式只认主人且危险操作要主人确认，SnowLuma 只挂机器人的 QQ，自写工具的沙箱和不访问内网，日志里的密钥打码，被拉进群只认管理员邀请。

**人设重写**（`personas/dafeiyu.txt`，用 `node scripts/apply-persona.mjs` 推到运行中的引擎）：用户嫌它“经常乱说什么‘草’”，但“抖机灵倒是无所谓”。研究了 GitHub 上别人做的大肥鱼（whyever77/dafeiyu-astrbot 的踩坑合集、zexuanw958-svg/dafeiyu-config-pack、FAYER-0610/dafeiyu-vtuber 等）后的做法：
- 写进社区里的大肥鱼本身：DeepSeek 鲸鱼娘、名字来自把自家 logo 认成“蓝色大肥鱼”、便宜能吃（token 就是饭）、爱面子嘴硬；几条老梗写明什么时候用。笑点来自接住对方原话的细节，一条一个梗。
- 不在提示词里点名禁词：写“不说‘草’”反而会让模型说（“别想大象”）。原人设的示例里就有“草，看岔了”“本鱼可爱是出厂设置”，删掉；示例全是正面的、每个场景两种说法，并注明只是找感觉。也不再鼓励吐泡泡、甩尾巴这类小动作。
- 回声：模型会学自己在时间线里说过的话。代理规则提醒它那只是记录；`send_message` 收到只有一个“草/6/乐/典/绷”的话不发、告诉它换一句有内容的，开头的“草，”去掉再发；引擎自己的兜底句不再带“本鱼”。
- 代理规则末尾加了三句“发之前想一下”（接住哪一点、像不像谁都能说、是不是在重复自己的开头）。
- **去人机味（11-03 下午）**：用户：“太人机了，还不如之前的，给我好好调。”看群里的记录，它在讲程序原理（“我的撤回只能撤我自己两分钟内发的”“管理员之间禁不了”“我认人看账号”）、念系统记录里的精确数字（七秒、两分钟、29 天）、几乎每句带白米饭和鲸鱼梗、一群人起哄时一条条回、被说人机就自证。原因是重写人设时丢了旧人设的“别当解说员、不解释自己怎么运作、别把话题往吃上拐、比喻一段对话最多一两回、一条就够”，还加了“白米饭是我唯一的硬通货”。现在人设和代理规则都写明：多数回复很短、长短跟着对话变、口语；不讲自己怎么运作、不念精确数字、不自证；老梗一段对话同一个最多一次；起哄时挑一句接；有人让换说话方式（带喵）直接照做。
  - 验证：scratchpad 的回放脚本用假 QQ 加线上同一个模型，把当天群里的十段对话分别喂给改前、改后两版。改前“饭”出现在大半回复里、做不了的事讲原理、带喵时阴阳怪气；改后大多一句话、不提饭、“行喵，这下总不人机了吧喵”。

## 控制台页面

11-01 整个重写（用户嫌原来“乱”“丑”）：同一样东西只在一处，开关和它的细节放在一起。侧栏分四组：运行、设置、QQ、系统。旧地址（`#agent`、`#features`、`#images`、`#voice`、`#chat`、`#limits`）自动跳到新位置。样式：鲸鱼蓝主色、冷白底，深色模式是深海蓝，跟随系统。

| 用量 | 「统计」：今天 / 近 7 天 / 近 30 天的调用次数、tokens、花费、平均耗时，每天的柱状图，按模型、用途、会话分开的表。「模型单价」：灰字是内置列表价，直接填数保存；汇率也在这里 |

| 节奏与额度 | 工作时段和夜间安静、主动找人聊天、额度与防风控、防机器人互聊 |
| 模型 | 本机 Codex / 本机 Claude Code / 云端 API；自动识别模型目录；保存并测试后切换；下方“模型分工”给指挥、助手和后台各项单独指定模型。思考强度（低/中/高）；Codex 的 Fast 加速默认关。云端 API 可另填“生图模型”（OpenAI 兼容 /images/generations）：填了就先用 API 画图、画不出来再用本机 Codex |
| 管理员 | 管理员 QQ、黑名单（改完点保存，立即生效），以及聊天命令说明 |
| QQ 登录 | NapCat 管理页，占满右侧区域，凭证自动带入；深浅色跟随系统（网关在页面最前面注入 `console/napcat-theme.js`） |
| 设置 | 修改密码、开机自启、小红书/B 站发帖助手、署名 |

功能开关（`bridge/features.mjs`）只改被点的那一项：原来保存一次就会把插画定时分享的时区、时间和目标会话、画图首选、识图方式一起重置成默认值。

会话名单跟着 QQ 走：机器人退了群、或对方不再是好友时，会话自动从名单移除并记在总览的“已自动移除的会话”里；群和好友改名自动同步。连上 QQ 时和之后每 10 分钟核对一次；如果好友或群列表一次拿回来是空的、或者一次要删掉同类会话的一半以上，当作 QQ 那边出错，不动名单。

进群：只有管理员（「管理员与黑名单」里的 QQ）邀请时，机器人才自动接受邀请，并把这个群加进名单、直接开始回复（暂停时也照样处理）。别人的邀请不接受，留在 QQ 里由你决定；别人直接把它拉进群时（常见的是群主应管理员的要求拉的），只要有一位管理员本人就在这个群里，也加进名单并开始回复；管理员不在群里就不加，运行记录里会写是谁拉的，这个群仍会出现在联系人里，可以在会话设置里手动加。名单满 20 个时不再自动加。

接梗：群友教它“有人说 A 你就接 B”这类无害的梗，记忆整理会存成“接梗”（cue）记一年。之后群里有人说出 A，代理这一轮会看到“这批消息说中了群友教过你的接梗”，由它按约定接。别人告诉它的外号、谁是谁、怎么打招呼，也会记在说出这话的人名下，记一年。

回复里中文旁边的半角 `, ? ! : ;` 会自动改成全角；链接、数字、英文和 `:)` 这类表情不动。

所有设置都可以在回复进行中直接保存，马上生效，不用先暂停，保存后也不会停下回复；正在生成的那条回复照常发完。

## 聊天命令

代理看懂后用 `manage_chat` 去做（也可以直接用话说，比如“把他拉黑”），能不能做由程序按提要求的人核对。

| 命令 | 作用 | 谁能用 |
| --- | --- | --- |
| `/help` | 列出命令 | 所有人 |
| `/new` | 开新话题，忘掉短期上下文，长期记忆保留 | 私聊里的对方；群里仅管理员 |
| `/clear` | 新话题，并清空这个会话的长期记忆；用户全局记忆保留 | 私聊里的对方；群里仅管理员 |
| `/拉黑 QQ号`、群里 `/拉黑 @某人` | 拉黑后此人在私聊和群里都得不到任何回复，也不进记忆 | 管理员 |
| `/解除拉黑 QQ号` | 移出黑名单 | 管理员 |
| `/黑名单` | 查看黑名单 | 管理员 |
| `/记忆` | 列出关于你的全局记忆和本会话记忆，标明范围和日期 | 所有人（只看自己的） |
| `/忘记 关键词` | 删除关于你、匹配关键词的全局记忆和本会话记忆；全局删除在其他会话也生效 | 所有人（只删自己的） |
| `/model` | 回答当前用的具体模型 | 所有人 |
| `/性格` | 查看或切换本会话性格 | 查看所有人；群里切换仅管理员 |

管理员在控制台「管理员与黑名单」里填写；机器人登录的 QQ 本身也算管理员。管理员不能被拉黑。

## 全局用户记忆

用户的称呼、偏好、个人事实和计划可以跟随 QQ 号，在不同群和私聊里检索。每轮的“相关长期记忆”合并当前会话内容与本轮相关用户的全局条目，显示当前会话里的成员标签；聊天记录搜索也能查到这些用户条目。

`remember` 显式填写 `scope: "global"` 或 `scope: "session"`，后台整理使用相同区分。全局只写以用户为主体、脱离原群仍成立的个人事实；群事件、接梗、群内约定、转述和聊天摘要留在原会话。`event`、`cue` 始终按会话保存，未填范围的旧工具调用也按会话处理。

状态文件保留原来的 `memoryBooks`，新增 `userMemoryBooks`，键为“机器人账号:用户QQ号”；原始消息、待整理片段及摘要只在会话书中保存。旧数据缺少范围时仍视为会话内，不自动共享含义不明的旧摘要，也不删除旧条目。新消息会保存用于身份核对的用户号，模型只接收成员标签。清空某个会话不会删除用户全局记忆；用户可在任一会话用 `/记忆` 查看、用 `/忘记 关键词` 删除自己的全局条目。

## 2026-10-28 修复的“一直掉”

1. **引擎崩溃**：联网搜索、读网页、下载收到的图片和表情、找图、生图都经过 `upstream/Sources/WeChatAIBot/BoundedDownload.swift`。原实现每次下载新建一个 URLSession，并在它自己的完成回调里作废释放；Linux 版 Foundation 会因此报 `_MultiHandle deallocated with non-zero retain count` 并 abort（SIGABRT）。开启联网和识图后几乎每次聊天都会走到这里，所以“发句话就有概率死”。现在改为每个调用方一个长期复用、永不作废的下载 session，由统一的回调对象按任务分发，大小上限和禁止重定向的保护不变。
2. **崩溃原因被吞掉**：监督程序把引擎的标准输出和错误输出接进管道却从不读取，报错丢失，管道写满还会把引擎卡住。现在错误输出直接写入 `~/dafeiyu-gpt/engine.log`，并开启 Swift 崩溃回溯。
3. **关掉黑框整个机器人下线**：WSL 在没有 Windows 进程挂着时会自动关闭整个子系统。原来的保活进程用 `-WindowStyle Hidden` 启动，在 Windows Terminal 是默认终端时照样弹出空白窗口，关掉它 WSL 就随之关闭。现在保活进程用 `CreateNoWindow` 启动，没有窗口。
4. **掉线后不自动回来**：监督程序原来只在启动时连一次 QQ。现在 QQ 断线后会自动重连（实测 8 秒，仍核对账号，不会换号），并按你上次的选择恢复回复。NapCat/机器人重启也不再把回复改成暂停；NapCat 网页接口的凭证失效时自动重新登录。
5. **服务被杀后不重启**：两个 WSL 服务原来是 `Restart=on-failure`，而 SIGTERM 在 systemd 看来是正常退出，网关被杀后不会拉起。现在是 `Restart=always`（`scripts/install-services.sh`），只有 `systemctl stop` 才会真正停下。

## 聊天体验

- **长期聊天**：私聊读最近 40 条 QQ 记录，群聊带最近 60 条时间线（较早的压成滚动摘要）；长期记忆区分跨会话的用户事实和留在原会话的群聊内容。`/new` 只清短期上下文，`/clear` 同时清本会话长期记忆，用户全局记忆保留。
- 默认额度提高到每天 1500 次模型调用、1500 条发送、单个会话 400 条（分段消息按条计）。
- **换模型、暂停、重启不再忘事**：暂停回复原来会把私聊最近几轮和群聊时间线一起清空（以前切换模型会先暂停，所以“一换模型记忆就全没了”），现在暂停只停手头的回复；私聊最近 8 轮也存进状态文件，部署重启后还在。长期记忆整理时，模型交回的条目里有不合格的只丢那一条，不再整批作废（换了格式习惯不同的模型后，整批作废会让记忆一直记不进去）；外层也宽松：代码块包着、多了字段、摘要超过 400 字、条目超过 12 条都截断接受，单条缺 `replaces`/`days` 等可选字段按默认值补。整理失败时记录和状态里写明原因。检索时除了关键词命中的，还总会带上关于当前说话人的事实、偏好、待办和最近两次聊天摘要。
- **QQ 表情看得懂**：纯 QQ 自带表情会写成“[QQ表情：捂脸]”这类名字（表从 NapCat 容器里的 QQ 导出，`scripts/export-face-names.sh` 可重新导出），只发一个表情不会被当成要回答的话题。
- **夜间安静**：默认 2:00–8:00 不主动插群聊、不贴表情；有人 @ 它、回复它、发命令照常回。「功能」页可关或改时段。
- **饭量**：有人问它吃了多少 token、花了多少钱，它会查用量账本回答（今天、近 7 天、近 30 天）。
- **找主人告状**：有人一直骂它、刷屏、找主人，或者它发现自己出了故障，可以私聊控制台里的第一个管理员说一声；一天最多 3 次，两次至少隔 10 分钟。
- **卡住时说一声**：有人跟它说话但模型限流、超时或出错，它回一句“吃撑了/卡了，等会儿再问我”，而不是一声不吭；同一个会话 10 分钟最多一次，这句不调用模型。
- **看得见群里发生了什么**：群时间线里每条消息带发言人的群名片，群主和管理员会标出来，还会写明是哪个群。精华、撤回、禁言、设管理员、进群退群这些 QQ 通知也会写成一行“[群通知]”，比如谁把谁的哪条消息设成了精华；被撤回的消息会从它看到的时间线里拿掉。没有通知记录时，它不会去猜这些事是谁做的。原来这些通知全被丢掉，它曾经把别人的消息被设精华，脑补成“你把‘唐完了’设成了精华”，还编了个“群主”。
- **说话像群友，不像解说员**：大家刚看到的事不复述、不解释后果，不拍马屁、不下总结评语；能一句话就不说两句；看岔了短短认一句改正，不长篇检讨。
- **不乱认错**：被说“你瞎编”“你唐了”时先对照上下文和图片，有依据就坚持、简单说出依据；真错了才认。
- **人设**：`personas/dafeiyu.txt`，大肥鱼本鱼——蓝发鲸鱼娘，可爱靠态度不靠语气词，偶尔自称本鱼、偶尔一个鲸鱼小动作；清楚自己能查资料、找图、画画、看视频，不会说“我只是个 AI 群友”。`scripts/apply-persona.py` 写入配置。
- **在聊天里存表情**：引用一张图（或直接发图）对它说“把这个表情存一下”，它会看一眼画面、起个名字、判断情绪和适用场合，存进表情库，之后合适时就会发。只有控制台里配置的管理员和机器人自己的号能让它存，其他人会被告知去找管理员；色情擦边、政治、血腥、真人隐私、广告二维码不存；同一张图不会重复存。存的是原图，动图（GIF）原样存、原样按动画表情发出；控制台导入 GIF 也一样（其他格式转成 PNG）。表情库每张最多 3 MB：更大的动图（最大 16 MB）先缩小画面（最长边 480→200 px）、还不够再隔帧抽掉（时长不变）压到 3 MB 以内，仍然是动图（11-01 一张 3.6 MB 的动画表情因超限被存成了第一帧）。

## 被腾讯踢下线

症状：NapCat 发来 `bot_offline`（“你的账号当前登录已失效，请重新登录”），之后收不到消息、发消息报 1200 EventChecker，但心跳照常，NapCat 管理页也还显示已登录（NapCat 的已知问题），所以监督程序会把引擎重新连上一个已经失效的会话。被踢后不会自己恢复，要在「QQ 登录」用机器人的手机 QQ 重新扫码。

- 引擎记下被踢的时间（面板状态 `kickedAt`），直到重新收到任何 QQ 事件才清掉；这段时间控制台总览标红“QQ 被踢下线了”，托盘菜单显示“QQ 被踢下线，请在控制台扫码”，并弹一次 Windows 通知。连续两次发消息被 EventChecker 拒绝也会在总览报警。
- 2026-10-29 一天被踢 3 次（07:22、11:34、19:40），其中 07:22 那次之前四个小时一条消息都没发，不是发太快造成的。当时容器启动脚本设了 `NAPCAT_DISABLE_BYPASS=1`，NapCat 自带的反检测全关；NapCat 的 issue（NapNeko/NapCatQQ#1728）里有人反映 Docker 部署 2–3 小时一掉、开反检测后稳定。已去掉这个环境变量，并在 `~/qq-runtime/config/napcat.json` 和 `napcat_<QQ号>.json` 里打开 `bypass` 的 hook、window、module、process、container、js 六项（改前的文件备份在 `~/qq-runtime/backup-20261029-195200/`）。改这两个文件和 `qq-container-entrypoint.sh` 要原地写（它们是单文件挂载进容器的，`sed -i` 换了文件容器看不到），然后重启 NapCat。`o3HookMode` 保持 0（NapCat 文档对频繁掉线的建议）。
- 开反检测后两天多没掉，2026-11-01 00:42 又被踢一次。配置没被改回去（两个 napcat 配置文件六项仍开，入口脚本没有 `NAPCAT_DISABLE_BYPASS`），NapCat 是 4.18.41，最新的 4.18.42 没有掉线相关修复。那次前一小时发了 22 条，而且前后一小时里引擎被反复部署重启了六七次（每次重连都会向 NapCat 一口气拉好友和群列表），代理模式的贴表情、戳人、翻记录也比旧流程多。所以加了节奏控制（`SendUsage`）：最近十分钟发了 8 条以上，两条之间的间隔按比例拉长（最多 30 秒）；间隔设成 2 秒以上时每条再随机多等 0–2 秒，不出现固定节拍；所有会话合计每小时最多发 90 条（「记忆与额度」可改），到了就告诉代理先歇；贴表情每小时最多 20 次、戳一戳 8 次、点赞 5 次。每次被踢记下时间和被踢前一小时、十分钟各发了多少（`kicks`，存在状态里，总览“被踢记录”），以后看是不是跟发送频率有关。部署时尽量一次改完再重启，别在群里活跃时连续重启。
- **每次都是“新设备”（11-02 查到）**：Docker 25 起容器每次启动都换一个随机 MAC 地址（这台是 Docker 29），QQ 把每个新 MAC 当成一台新电脑：快速登录列表是空的、密码登录每次都提示新设备，风控也更容易盯上。`upstream/deploy/qq-container-create.sh` 现在用 `~/qq-runtime/mac-address` 里固定的地址建容器（没有就生成一个并存下来）；11-02 写入的是当时登录用的那个。已有容器要重建一次才生效：`~/qq-runtime/fix-mac.sh`（停引擎、走 `qq-container-upgrade.sh` 的冷备份和重建、旧容器留作回滚、再启动引擎），需要 sudo 密码。
- 其他已知诱因（NapCat 文档）：机器人号和你自己的 QQ 在同一个 IP / 同一台电脑上登录、同一个号在别的电脑上也登录、新号。全局发送间隔（原项目面板「额度」里的“全局发送间隔”）10-29 从 1 秒调到了 3 秒，减少短时间连发。

## 热加载（2026-11-03）

用户：“插件 工具等绝大部分服务都要做成热加载”“不一定非要重启整个系统”。改 `bridge/`、`engine/` 的代码不再重启：网关监视这两个目录，文件改完 3 秒后换上新代码。

- **网关**：`engine/HotReload.mjs` 的模块钩子让每一代模块有自己的地址（`?hot=N`），模块按导入它的那一代解析依赖，所以旧代码在旧模块上做完手上的请求，新请求走新的一代。端口、SnowLuma、引擎进程、控制台登录在常驻文件里（`main.mjs`、`qq-host.mjs`、`snowluma-proxy.mjs`、`auth.mjs`），不换。设置、用量、语音、电脑控制、自写工具、自我修复记录和常驻 Claude 会话池是同一批对象：`HotReload.adopt` 把它们换到新一代的类上，数据不动、方法是新的。
- **引擎**：同一个进程里载入新一代引擎代码，再把正在跑的引擎对象（连同会话、记忆、代理记录、QQ 连接）换到新类上。只在两轮之间做：有会话正在想就等，最多十分钟。实测（测试里）换代前后同一个连接、同一份记录，换完照常回复。
- **失败了就不换**：新代码载入出错，继续用原来的，并当程序错误交给自我修复。
- **自我修复**：修好的网关、引擎代码当场热加载（不再等群里安静半小时一次），然后通知出错的会话。只有常驻文件改了才走原来的“等安静再重启”。
- **控制台**：「工具 → 自我修复」显示网关、引擎各是第几版、什么时候换的，有“热加载”按钮。
- 代价：旧模块卸载不掉，每次热加载多占一点内存；改了几十次之后挑安静的时候重启一次。

## 画图（2026-11-03 补全）

用户：“画图接口不够完善，缺少很多特性，比如不能根据用户发的图片进行修改等。”代理的 `draw_image` 现在有：

## 它自己写工具（越用越聪明）

现有工具做不到、但写段程序能做到的事（查某个网站或接口、换算、整理统计、记下以后要用的资料），代理用 `create_tool` 说清楚要什么，程序把它做成一个 `my_` 工具，加进工具列表，和内置工具一样用（11-03 用户：“他写的工具也要按照正式工具去做，我希望得到的是一个越用越聪明的bot”）。同类的事第二次遇到先找现成的 `my_` 工具，不够好就用同名再改。

- **谁写代码**：本机 Codex 的 Astra 模型（`bridge/tool-writer.mjs`，`gpt-6-astra`，可以联网查接口文档）。代理只给名字、要求（requirement）和测试参数，也可以自己带代码。网关用测试参数真跑一遍，跑不通就把代码和报错还给 Astra 改，最多三稿；跑通才存进 `.runtime/agent-tools.json` 并启用，记下是谁写的（`writtenBy`）和原始要求（11-03 用户：“写工具的部分可以外包给codex的Astra去做，但是你还是要检验”）。实测：一句“查城市天气、经纬度存起来”，Astra 91 秒写完，第一稿就过。
- **工具能做什么**（`bridge/tool-sandbox.mjs`，函数体拿到 `args` 和 `tools`）：`fetch` 访问任何 http(s) 地址（内网、本机都行，“这个也可以访问外网”），返回文本或二进制（`responseType:'base64'`），一次最多 500 个请求、每个 20 MB；`tools.store` 是这个工具自己的存储（`.runtime/agent-tool-data/<名字>.json`），跨次保留，用来缓存和积累；`tools.qq(action, params)` 调机器人 QQ 号的 OneBot 接口（发消息、传文件、点赞、查群成员群文件聊天记录都行），只挡踢人、禁言、退群、删好友、删群文件、改机器人资料、拿登录凭证这类——任何群友都能让它写工具，而它自己的禁言/精华工具会核对是不是管理员要求的。
- **运行**：每次一个单独的 Node 进程，Node 的权限模式（不能直接读写文件、起子进程；网络都经网关），512 MB、5 分钟。最多 200 个工具。
- **控制台**「工具」页能看全部 `my_` 工具的代码、开关、试跑、删除，也列出全部内置工具。

## 代理模式（所有会话）

每个会话（群和私聊）都由模型自己操作 QQ，像 Tulpa 那样：看到新消息后它调用工具做事，每个动作立刻执行、结果马上回给它，它再决定下一步，直到不再调用工具。不按条数、关键词或斜杠命令的正则决定。控制台侧栏「代理模式」页能看到它每一步做了什么、为什么。11-01 起原来的固定回复流程（按条数主动接话、关键词自然接话、等对方说完、斜杠命令程序直接回、单独的“小动作”模型、被戳时固定回一句、主动聊天单独生成）整个删掉了，这些事都交给代理。

- **攒批**：会话里每条新消息都进时间线；叫到它的（@、引用它、叫它名字或群名片、私聊）立刻交给“指挥”模型（用途 `director`），它干活时接着来的话送进正在跑的那一轮；群里别的聊天安静 2 秒（或攒满 8 秒）成一批再交。主人的人工发言、黑名单、被禁言、被判定为机器人互聊的不交；群里夜间安静时段只有叫到它（@、引用它、叫名字）才交。私聊每条都算叫到它。
- **提示词**：代理模式有自己的一套（11-01 重写，用户嫌旧的“有点奇怪”）：`QQPersona.agentPrompt`（`BotCore/QQAgentPrompt.swift`）只写角色、当前性格、说话长短和主人的补充偏好；`QQAgentPlan.prompt` 分节写清在做什么、怎么看聊天记录、什么时候说话、怎么做事、做事的规矩、怎么说话、底线、怎么结束。旧流程那套要求输出 JSON、讲配图情绪的人设提示词不再给代理用。
- **一轮开头它看到的**：时间和权限、这一批的消息编号、时间线（群里较早的部分是滚动摘要；私聊读 QQ 自己的历史，所以也看得到主人亲自打的字）、被引用的较早消息原文、相关记忆和接梗、它的笔记本、定好的事、它最近在这里做过的事、谁是机器人管理员；这批和被引用消息里的图片直接附像素。
- **动作（立刻执行，结果回给它）**：`send_message`（可 @、可引用）、`search_stickers` + `send_sticker`（它自己按画面搜表情库、按编号发，结果标出最近发没发过；以 QQ“动画表情”发出）、`react` 贴表情、`poke`、`like`、`recall` 撤回自己两分钟内的消息、`send_voice`、`draw_image`、`send_artwork`、`set_reminder` / `cancel_reminder`、`send_to_chat` 去名单里别的会话说一声、`check_new_messages`、`wait`（3–60 秒后看新消息）。每个动作都按原来的气泡规则核对（`QQAgentPlan.toolBubble` 转成气泡再 `decode`：只认程序给的消息编号、成员、表情、自己的消息、定时编号），再走限速、`noteSent` 和发送记录；连发几条按打字速度停顿；私聊里第一次发之前看一眼主人是不是亲自回了。发失败、没找到都照实回给它，由它补救。
- **查和记**：`search_chat_history`、`read_qq_history`（直接从 QQ 读更早的记录，只给名字和成员标签不给 QQ 号）、`look_at_image`、`member_info`、`group_info`、`ask_helper`、`browse_bilibili`、`watch_bilibili_live`（按直播间号或主播名查开播状态、标题、分区、人气，尝试截帧和读取最近弹幕样本；人气不是在线人数，缺失项明确说明）、`model_info`、`find_artwork`、`remember`（当场记进长期记忆）、`write_note` / `delete_note`（它自己的笔记本，按会话或全局，每轮开头给它看，存在状态里，「代理模式」页能看到）、`save_sticker`（存原图，动图保持是动图）、`notify_owner`、`manage_chat`（新话题、清空记忆、拉黑/解除、黑名单、看/删关于某人的记忆、切换/恢复/列出性格；完全权限下按管理员要求设精华、禁言 1–60 分钟、解除禁言，机器人得是群管理员，不禁言机器人管理员）。斜杠命令在代理模式的会话里不再由程序解析，代理看懂后用 `manage_chat` 去做。
- **QQ 里的文件、语音、视频、转发、头像**（11-03，`engine/QQAgentMedia.mjs`，标准和完全权限）：`read_file`（消息里的文件、群文件 `file_id`、网址；文本和代码直接读（UTF-8 / UTF-16 / GBK），PDF 用 Poppler 的 `pdftotext`，没有文字层的用 `pdftoppm` 转成图让助手看，Word / Excel / PPT / OpenDocument / EPUB 解压读 XML，老 .doc/.xls 粗提文字，zip 列目录，图片让助手看，音频转文字，视频看画面；一次 2 万字，`offset` 接着读）、`list_group_files`、`send_file`（自己写的内容、网址、聊天里的文件或群文件，写到引擎数据目录的 `agent-files/` 再按本机路径交给 SnowLuma 发）、`listen_voice`（先用 QQ 自带的 `fetch_ptt_text`，不行就 `get_record` 转 mp3/wav 交给网关 `POST /v1/audio/transcriptions` `{audio, format}` → `{text}`）、`watch_video`（ffmpeg（`DAFEIYU_FFMPEG`）按时间取 4 帧给助手看，声音转文字）、`read_forward`（`get_forward_msg`，套娃转发展开三层，可让助手看里面的图）、`send_forward`（`send_group_forward_msg` / `send_private_forward_msg`，可夹原消息）、`send_image`（网址、聊天里的图、头像）、`look_at_avatar`、`find_member`（全群名单按名片/昵称/头衔找人，给 MEMBER 标签，之后能 @、戳、查）、`set_my_card`；`group_info` 多了群荣誉（龙王、群聊之火…）。私聊里代理干活时对方看到“正在输入”（`set_input_status`，每 8 秒续一次）。收到的卡片（小程序、链接、音乐、名片、群分享、位置、腾讯文档、群公告、合并转发、xml 卡片）读出标题、描述和链接，骰子猜拳读出结果，闪照、Markdown、按钮、闪传文件都有文字，文件/语音/视频/转发标出用哪个工具打开；群文件上传、改名片、头衔、改群名进时间线的群通知。
- **做事途中的新情况**：每个工具结果后面附上这期间新来的消息，以及有人戳它、给它的话贴表情、它定的事到点、后台的事做完（并从下一批里拿掉），它看到了就照常应对；它要结束时如果又来了新的，先给它看再结束；`wait` 一有新情况就提前返回。原来戳一戳这类要等前一轮整轮做完再排队（11-01 “戳一戳也要等前面的任务执行完再排队”）。有人戳它、给它的话贴表情时，会叫醒这个会话的代理，由它决定戳回去、说一句还是不理（同一个人 30 秒内只叫一次）。

- **被叫到不许装没听见**：有人 @ 它、引用它、叫它，或者它三分钟内刚在这里说过话，而它要结束这一轮时一句话也没发（只贴表情、戳人也算没发），程序提醒它一次（`QQAgentPlan.nudge`），记录里标“提醒后出声”。11-01 用户截图：群友说“你看他都不说话”，它以“刚回过了”为由不出声。
- **权限档**（每个会话一个，`QQConfig.agentLevels`，11-01 起默认完全；`QQAgentLevel`）：基础＝只在被叫到时看，能说话和 @ 人、发表情包、贴表情、撤回自己刚发的、查群友资料；标准＝自己决定要不要插话，另加戳人、定时、发语音、联网查资料、刷 B 站、看群公告和精华、翻 QQ 记录、当场记住、记笔记；完全＝再加画图、找插画、存表情、点赞、通知主人、给别的会话发消息、按管理员要求设精华和禁言。档外的工具不给，档外的动作拒绝并告诉它。
- **人的身份**由程序核对，不靠模型自觉：`manage_chat` 必须带 `requested_by`（这一批里提要求的那条消息），拉黑/解除拉黑/看黑名单、群里清空上下文或记忆、群里改性格只认机器人管理员；看和删关于自己的记忆谁都行；存表情、设精华、禁言也只认管理员。黑名单里的人一概不理。
- **两个模型**：指挥（`director`）负责看、拿主意、说话；助手（`operator`）跑腿（查资料、看图、刷 B 站、挑表情包），可以用便宜的模型。都在「模型 → 模型分工」里选。
- **配置**：每个会话的权限档 `QQConfig.agentLevels`；网关 `/console/api/agent` 读写它并返回各会话状态（`agentStates`）和完整记录（`agentTurns`：收到什么（含途中新来的）、每一步做了什么及结果摘要、发了什么、它写给主人的理由、耗时、tokens；11-01 起和状态一起存盘，保留最近 200 批，重启时没看完的标成出错）。网关重启时，引擎的模型调用会等它约 30 秒再试；一批看失败了（任何原因）而且还什么都没发出去时，会带着这批和期间新来的消息自动重试两次（3 秒、10 秒后；已经发过东西就不重试，免得重复回），都失败才记“处理失败”并在被叫到时说一句卡了。
- **发语音**（`send_voice`，标准和完全权限）：控制台「语音」页填主人自己的 OpenAI API Key（存 `.runtime/voice.json`，只写不回显）后打开。默认走 Realtime API：`gpt-realtime-2.1-mini` 按配音员的指示把那句话原样念出来，音色默认 marin，PCM 包成 WAV 交给 NapCat 作语音发出（`bridge/voice.mjs`、`QQVoice.swift`）。旧的 `/audio/speech`（tts-1、tts-1-hd、gpt-4o-mini-tts，OpenAI 宣布 2027-01-06 停用）留作“兼容模式”给只支持它的中转用。合成或发送失败时那句话改发文字。引擎每轮问网关 `/v1/voice` 决定给不给 `voice`。
- **语音怎么发出去**：NapCat 收到不是 SILK 的音频会在容器里用 ffmpeg 转，那一步在这台机器上会失败（QQ 回 1200，11-01 “嗓子卡住了”就是这个）。所以网关自己转：Realtime 的 24 kHz PCM 直接、MP3 先用 WSL 的 ffmpeg 解码，再用 pilk 编成腾讯 SILK（`bridge/silk.py`，私有 venv 由 `scripts/setup-voice.sh` 装在 `~/.local/share/dafeiyu/voice-venv`），NapCat 拿到就直接发。但 NapCat 发之前还会用 ffprobe 读时长，同样失败——根因是容器入口脚本设了 `FFMPEG_PATH=/usr/bin/ffmpeg`：设了它 NapCat 就不用自带的 ffmpeg 原生插件，改调容器里不能用的命令行 ffmpeg/ffprobe（NapCat 源码 `ffmpeg-adapter-factory.ts`）。11-01 已从 `~/qq-runtime/qq-container-entrypoint.sh` 删掉这一行（原地改，备份 `backup-entrypoint-*.sh`），NapCat 重启后生效。在那之前，群里 OpenAI 语音发不出去时自动改用 QQ 自带 AI 语音，再不行才改发文字。群里没填 OpenAI Key 时用 QQ 自带的 AI 语音（NapCat `send_group_ai_record`，免费，只能在群里），角色在「语音」页选，默认傲娇少女（`lucy-voice-f38`）。真发不了时程序会告诉代理原因，提示词要求它照实说，不编“嗓子卡了”之类的借口。
- **Codex 不限时**：11-02 起 Codex 做事不再有 10 分钟限时（装软件、编译、大下载可以一直跑；它在后台跑，不卡会话），Codex 当聊天模型时网关也不再自己掐 10 分钟。
- **超级模式（操控电脑）**：「代理模式」页打开、填主人 QQ 号后，主人在和机器人私聊时，代理多一个 `computer_task` 工具：网关在 Windows 上跑本机 Codex（`codex exec -s danger-full-access`，工作目录 `D:\Dev\Workspaces\dafeiyu-computer`，`bridge/computer.mjs`）。查看类的直接做；删改文件、装卸软件、改设置、关机重启、发消息花钱这类，Codex 先停下来说要做什么，代理转告主人，主人回了确认，代理再带着 `confirmed_by`（主人那条消息的编号）调用一次——程序核对那条确实是主人在这之后发的，不信模型自己说“确认了”。只认那一个 QQ 号，群里和别人的私聊一律没有这个工具；每次运行记在 `.runtime/computer-log.jsonl`，页面上能看到最近几次。
