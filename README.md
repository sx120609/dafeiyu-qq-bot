# 大肥鱼 QQ 机器人 · 本机部署

基于 [SAKURAfan1023/dafeiyu-bot](https://github.com/SAKURAfan1023/dafeiyu-bot)，上游版本 `cc8170396bc68266077204576f8469e414b5c44c`。原项目接 DeepSeek，这里换成本机模型：本机 Codex（复用 ChatGPT 登录）、本机官方 Claude Code，或自己的云端 API，在控制台里切换。QQ 引擎、人格、表情、会话记忆和原面板保留。

## 日常使用

- **启动**：双击 `Dafeiyu.exe`（或 `Start.cmd`）。它在后台拉起 WSL、Docker、NapCat 和机器人，不弹任何终端窗口，托盘里出现大肥鱼图标，然后打开控制台。
- **托盘菜单**：打开控制台、暂停/开始回复、重启机器人、重启 NapCat、开机自启、停止大肥鱼并退出、只退出托盘（机器人继续运行）。双击图标也会打开控制台。
- **开机自启**：托盘菜单或控制台「设置」里开关，写入当前用户的 `HKCU\…\Run\Dafeiyu`，默认关闭。
- **控制台**：`http://127.0.0.1:18191/console/`，只监听本机。第一次从启动器或 `Console.cmd` 打开时设置密码，之后用密码登录；密码在「设置」里随时改，改完其他浏览器需要重新登录。
- **远程打开（frp 等隧道）**：设置过密码后，用隧道的域名访问 `/console/` 也可以，必须登录；直接打开 `/bot/` 或 NapCat 页面会先跳到登录。通过隧道只能用控制台和它内嵌的页面，模型接口 `/v1/*` 和启动器令牌只认本机地址。连续输错 5 次密码锁 30 秒，再错锁定时间翻倍（最长 1 小时）。隧道是明文 HTTP 时密码和登录 Cookie 会明文过网，建议在 frp 上配 HTTPS。
- **QQ 掉线需要重新扫码时**：控制台「QQ 登录」页直接扫。扫完监督程序自动核对账号、重连，并恢复到你上次的回复状态（在回复就继续回复，暂停就保持暂停）。
- `Stop.cmd` 停止全部组件；`Status.cmd` 查看状态。

会话名单跟着 QQ 走：机器人退了群、或对方不再是好友时，会话自动从名单移除并记在总览的“已自动移除的会话”里；群和好友改名自动同步。连上 QQ 时和之后每 10 分钟核对一次；如果好友或群列表一次拿回来是空的、或者一次要删掉同类会话的一半以上，当作 QQ 那边出错，不动名单。

进群：只有管理员（「管理员与黑名单」里的 QQ）邀请时，机器人才自动接受邀请，并把这个群加进名单、直接开始回复（暂停时也照样处理）。别人的邀请不接受，留在 QQ 里由你决定；别人直接把它拉进群时（常见的是群主应管理员的要求拉的），只要有一位管理员本人就在这个群里，也加进名单并开始回复；管理员不在群里就不加，运行记录里会写是谁拉的，这个群仍会出现在联系人里，可以在会话设置里手动加。名单满 20 个时不再自动加。

接梗：群友教它“有人说 A 你就接 B”这类无害的梗，记忆整理会存成“接梗”（cue）记一年。之后群里有人说出 A，不用 @、也不等接话计数，它就按约定接，同一个梗一分钟内只接一次，夜间安静时段不接。别人告诉它的外号、谁是谁、怎么打招呼，也会记在说出这话的人名下，记一年。

回复里中文旁边的半角 `, ? ! : ;` 会自动改成全角；链接、数字、英文和 `:)` 这类表情不动。

所有设置都可以在回复进行中直接保存，马上生效，不用先暂停，保存后也不会停下回复；正在生成的那条回复照常发完。

## 2026-10-28 修复的“一直掉”

1. **引擎崩溃**：联网搜索、读网页、下载收到的图片和表情、找图、生图都经过 `upstream/Sources/WeChatAIBot/BoundedDownload.swift`。原实现每次下载新建一个 URLSession，并在它自己的完成回调里作废释放；Linux 版 Foundation 会因此报 `_MultiHandle deallocated with non-zero retain count` 并 abort（SIGABRT）。开启联网和识图后几乎每次聊天都会走到这里，所以“发句话就有概率死”。现在改为每个调用方一个长期复用、永不作废的下载 session，由统一的回调对象按任务分发，大小上限和禁止重定向的保护不变。
2. **崩溃原因被吞掉**：监督程序把引擎的标准输出和错误输出接进管道却从不读取，报错丢失，管道写满还会把引擎卡住。现在错误输出直接写入 `~/dafeiyu-gpt/engine.log`，并开启 Swift 崩溃回溯。
3. **关掉黑框整个机器人下线**：WSL 在没有 Windows 进程挂着时会自动关闭整个子系统。原来的保活进程用 `-WindowStyle Hidden` 启动，在 Windows Terminal 是默认终端时照样弹出空白窗口，关掉它 WSL 就随之关闭。现在保活进程用 `CreateNoWindow` 启动，没有窗口。
4. **掉线后不自动回来**：监督程序原来只在启动时连一次 QQ。现在 QQ 断线后会自动重连（实测 8 秒，仍核对账号，不会换号），并按你上次的选择恢复回复。NapCat/机器人重启也不再把回复改成暂停；NapCat 网页接口的凭证失效时自动重新登录。
5. **服务被杀后不重启**：两个 WSL 服务原来是 `Restart=on-failure`，而 SIGTERM 在 systemd 看来是正常退出，网关被杀后不会拉起。现在是 `Restart=always`（`scripts/install-services.sh`），只有 `systemctl stop` 才会真正停下。

## 聊天体验

- **分条但不刷屏**：大多数时候一条；内容多时模型用空行分成两三条，一次最多 3 条（多出来的并进第三条），一条回复总长默认上限 500 字（面板可调，最高 2000）。查资料的回答先说结论和最要紧的两三点，不罗列、不分章节；不再自动在末尾附“来源：+ 链接”，对方要出处时模型再给。原来所有换行会被压成空格、硬截到 200 字，现在保留换行。
- **多步任务**：一次回复里模型最多可连续调用 5 轮工具（每轮最多 3 个），可以先搜、再打开页面、再换关键词搜，最后作答；本机网关单次调用超时 10 分钟以上，不会因为查资料慢被掐断。
- **长期聊天**：私聊带最近 8 轮对话和最近 40 条 QQ 记录，群聊带最近 60 条时间线；长期记忆照常按会话整理，人设里也要求熟了之后自然接上之前聊过的事。`/new` 只清短期上下文，`/clear` 连长期记忆一起清。
- **不靠关键词**：叫名字出现在句子任何位置都算叫它；刚回复过某人，那人接着说的下一句（90 秒内、群里上一句是机器人）就当作在接话，不再要求以“那/所以/为什么”开头。主动插群聊时也能联网。消息里出现“出处/谁画的/谷歌”等词不再把所有工具关掉；出现“图/画”不再额外多调一次模型。
- **解析不再一票否决**：回复 JSON 多一个字段、情绪写错、正文带网址，都照常发送，不再换成“这次回复没处理好”；网关收到多余或格式不对的工具调用时只丢掉那一个。
- 默认额度提高到每天 1500 次模型调用、1500 条发送、单个会话 400 条（分段消息按条计）。
- **打字节奏**：分段回复的第一条立刻发，后面每条按长度停顿再发（约每秒 6 个字，1.5–8 秒，带一点随机），不会一下子全甩出来。
- **等对方说完**：同一个人连着发几条，等他停下再合并成一次回复（默认最多等 5 秒，「功能」页可调或关掉）。看着没说完的（没有句号、问号、语气词这类结尾，又不长）等满，看着说完了只等一半。
- **看过的图记得**：群里有人 @ 它或接着聊时，最近 15 分钟群里发过的图（最多 3 张）会重新附上；私聊同样带上对方最近 15 分钟发的图（最多 2 张）。时间线里注明哪张图这次附上了、哪张没附上但当时看过。原来图片过了 3 分钟就只剩“[媒体未读取]”，它会以为自己没看过、把之前读图说的话当成瞎编然后认错。
- **省输入成本**：机器人的人设和规则现在每次都一模一样（当前时间、这轮是谁说的、这轮能用的表情候选、生图结果等每次会变的内容挪到了消息里），网关再把它们放进 Claude Code 的系统提示，由 Claude 的提示缓存按缓存价读取，一条回复的多轮工具调用也能共用。群聊时间线从约 9000 字减到约 5000 字；私聊历史里每轮只存对方说了什么（含引用）和它回了什么，不再存整段输入。
- **换模型、暂停、重启不再忘事**：暂停回复原来会把私聊最近几轮和群聊时间线一起清空（以前切换模型会先暂停，所以“一换模型记忆就全没了”），现在暂停只停手头的回复；私聊最近 8 轮也存进状态文件，部署重启后还在。长期记忆整理时，模型交回的条目里有不合格的只丢那一条，不再整批作废（换了格式习惯不同的模型后，整批作废会让记忆一直记不进去）。检索时除了关键词命中的，还总会带上关于当前说话人的事实、偏好、待办和最近两次聊天摘要。
- **QQ 表情看得懂**：纯 QQ 自带表情会写成“[QQ表情：捂脸]”这类名字（表从 NapCat 容器里的 QQ 导出，`scripts/export-face-names.sh` 可重新导出），只发一个表情不会被当成要回答的话题。
- **夜间安静**：默认 2:00–8:00 不主动插群聊、不贴表情；有人 @ 它、回复它、发命令照常回。「功能」页可关或改时段。
- **饭量**：有人问它吃了多少 token、花了多少钱，它会查用量账本回答（今天、近 7 天、近 30 天）。
- **找主人告状**：有人一直骂它、刷屏、找主人，或者它发现自己出了故障，可以私聊控制台里的第一个管理员说一声；一天最多 3 次，两次至少隔 10 分钟。
- **卡住时说一声**：有人跟它说话但模型限流、超时或出错，它回一句“吃撑了/卡了，等会儿再问我”，而不是一声不吭；同一个会话 10 分钟最多一次，这句不调用模型。
- **看得见群里发生了什么**：群时间线里每条消息带发言人的群名片，群主和管理员会标出来，还会写明是哪个群。精华、撤回、禁言、设管理员、进群退群这些 QQ 通知也会写成一行“[群通知]”，比如谁把谁的哪条消息设成了精华；被撤回的消息会从它看到的时间线里拿掉。没有通知记录时，它不会去猜这些事是谁做的。原来这些通知全被丢掉，它曾经把别人的消息被设精华，脑补成“你把‘唐完了’设成了精华”，还编了个“群主”。
- **说话像群友，不像解说员**：大家刚看到的事不复述、不解释后果，不拍马屁、不下总结评语；能一句话就不说两句；看岔了短短认一句改正，不长篇检讨。
- **不乱认错**：被说“你瞎编”“你唐了”时先对照上下文和图片，有依据就坚持、简单说出依据；真错了才认。
- **人设**：`personas/dafeiyu.txt`，大肥鱼本鱼——蓝发鲸鱼娘，可爱靠态度不靠语气词，偶尔自称本鱼、偶尔一个鲸鱼小动作；清楚自己能查资料、找图、画画、看视频，不会说“我只是个 AI 群友”。`scripts/apply-persona.py` 写入配置。
- **表情包**：不再固定每隔几条就发；最短间隔 10 分钟，由模型按语境决定要不要配图。
- **在聊天里存表情**：引用一张图（或直接发图）对它说“把这个表情存一下”，它会看一眼画面、起个名字、判断情绪和适用场合，存进表情库，之后合适时就会发。只有控制台里配置的管理员和机器人自己的号能让它存，其他人会被告知去找管理员；色情擦边、政治、血腥、真人隐私、广告二维码不存；同一张图不会重复存。动图存的是中间一帧。
- **找插画**：模型调工具找到图后保留它自己说的话，只在后面附一行画师署名，不再换成固定的命令菜单。
- **戳一戳**：有人戳大肥鱼会戳回去，有时（默认 50%）再顺口说一句，同一个人 30 秒内只回一次；「功能」页可调。

## 被禁言、发送失败

- 群里收到禁言通知（禁言本账号或全员禁言）就只停这一个群：照常记聊天和记忆，不回复、不贴表情、不戳回去；时间到或收到解禁通知自动恢复。运行记录里会写被禁言多久。
- QQ 明确拒绝一条消息（被禁言、被踢、风控等）记为“没发出去”，并顺手查一下是不是被禁言了；不再把它当成“发送结果未知”、更不会因此暂停整个机器人。原来一个群禁言会让所有会话都停掉。
- 真正不知道发没发出去（等回执超时、连接断了）的消息不重发，也只记一笔，不暂停。

## 被腾讯踢下线

症状：NapCat 发来 `bot_offline`（“你的账号当前登录已失效，请重新登录”），之后收不到消息、发消息报 1200 EventChecker，但心跳照常，NapCat 管理页也还显示已登录（NapCat 的已知问题），所以监督程序会把引擎重新连上一个已经失效的会话。被踢后不会自己恢复，要在「QQ 登录」用机器人的手机 QQ 重新扫码。

- 引擎记下被踢的时间（面板状态 `kickedAt`），直到重新收到任何 QQ 事件才清掉；这段时间控制台总览标红“QQ 被踢下线了”，托盘菜单显示“QQ 被踢下线，请在控制台扫码”，并弹一次 Windows 通知。连续两次发消息被 EventChecker 拒绝也会在总览报警。
- 2026-10-29 一天被踢 3 次（07:22、11:34、19:40），其中 07:22 那次之前四个小时一条消息都没发，不是发太快造成的。当时容器启动脚本设了 `NAPCAT_DISABLE_BYPASS=1`，NapCat 自带的反检测全关；NapCat 的 issue（NapNeko/NapCatQQ#1728）里有人反映 Docker 部署 2–3 小时一掉、开反检测后稳定。已去掉这个环境变量，并在 `~/qq-runtime/config/napcat.json` 和 `napcat_<QQ号>.json` 里打开 `bypass` 的 hook、window、module、process、container、js 六项（改前的文件备份在 `~/qq-runtime/backup-20261029-195200/`）。改这两个文件和 `qq-container-entrypoint.sh` 要原地写（它们是单文件挂载进容器的，`sed -i` 换了文件容器看不到），然后重启 NapCat。`o3HookMode` 保持 0（NapCat 文档对频繁掉线的建议）。
- 其他已知诱因（NapCat 文档）：机器人号和你自己的 QQ 在同一个 IP / 同一台电脑上登录、同一个号在别的电脑上也登录、新号。全局发送间隔（原项目面板「额度」里的“全局发送间隔”）10-29 从 1 秒调到了 3 秒，减少短时间连发。

## 主动找人聊天（默认关闭）

控制台「功能」页的“主动找人聊天”。只在私聊里：和某个好友一段时间没聊（默认 24 小时），大肥鱼会看自己记得的关于 TA 的事和最近的聊天，自己判断要不要发一条——比如问问之前说的考试、面试后来怎么样，或者轻松打个招呼；没有合适由头就不发，过几小时再看。

- 对方没回上一条主动消息，不会再发第二条；同一个人两次主动之间至少隔一段时间（默认 48 小时）。
- 免打扰时段不发（默认 23:00–9:00，北京时间）。可以取消勾选不想被主动找的人。
- 从没真正聊过、没有任何记忆的好友不会被主动找；需要打开「独立长期记忆」。
- 每个私聊旁边的“预览一条”会让模型现在生成一条看看，只显示、不发送。
- 一次检查只排一位好友，消息不会同时发给所有人；回复暂停时不发。

## 群里的小动作（贴表情、戳一戳、跟着复读）

控制台「聊天行为」页的“群里的小动作”。全部由模型决定，没有随机概率：群里有新消息时先攒着，群里安静 20 秒（或攒满 75 秒）后，把最近 20 行时间线交给模型看一次（用途 `react`，在「模型分工」里可以单独指定便宜的模型）。模型读到的：每条是谁说的、群名片和群主/管理员身份、是不是在叫它或引用它、有没有图、别人已经贴了什么表情几个人贴（NapCat 的 `group_msg_emoji_like` 通知）、它自己贴过的、正在复读的那句、和这些人相关的记忆、它最近做过的小动作、可用表情和你设的偏好、活跃程度。它回一个动作清单和一句理由，程序只执行它被允许、对得上编号的：

- 贴表情：只能贴这次的新消息，一条一个、一次最多三条，表情必须在列表里且偏好不为“不用”。QQ 不收的表情编号会被记下，之后不再给模型。
- 戳一戳：只能戳这段时间线里说过话、没被拉黑的人；同一个群十分钟最多一次；可在页面关掉。
- 跟着复读：只有两个以上不同的人连着发了同一句 1–20 字的短句、中间没有它自己时才会给这个选项；同一句半小时内只跟一次；走正常的发送登记（`noteSent`）；可关掉。

频率和花费：活跃程度“安静 / 适中 / 活跃”对应每个群每小时最多看 3 / 6 / 12 次，所有群合计每小时最多 30 次；同一个群两次至少隔“同一个群至少隔多久看一次”；当天模型调用用到上限的八成后停下，把剩下的留给回复。夜间安静、被禁言、时段外不看。每次看完做了什么、为什么，显示在页面下方“最近的小动作”（也在面板状态的 `interactions` 里，只在内存里，重启清空）。

表情列表在 `upstream/Sources/BotCore/QQReactions.swift` 的 `catalog`，每个带“什么时候用”的说明；默认最常用的还是 🍭 棒棒糖（147）、🐳 鲸鱼（128051）、❔ 问号（10068）、👊 拳头（120）。旧设置里保存过的偏好会保留，新加进表情列表的按默认偏好补上。表情编号可以用 NapCat 容器里 QQ 自带的表情对照表核对（`scripts/find-face-ids.sh 名字`，需要能用 docker）。

## 代理模式（试用）

「聊天行为」页的“代理模式（试用）”里勾选的群，不走下面那套按条数和关键词决定的流程，改成模型自己当群友（思路参考 Tulpa 的“先决定、再表达”）：

- 群友的每条消息都进时间线；群里安静 2 秒（或攒满 8 秒）就成一批，交给“指挥”模型（用途 `director`，默认跟随当前连接）。主人的人工发言、黑名单、被禁言、被判定为机器人互聊的不交；夜间安静时段只有叫到它（@、引用它、叫名字）才交。
- 指挥看到：人设和群聊规则、群时间线（较早的是滚动摘要）、这一批的消息编号、相关记忆和接梗、它最近在这个群做过的事、可用的表情回应；这批里的图片直接附上像素。它可以先跑腿再决定：`search_chat_history`（本机翻聊天和记忆）、`look_at_image`（让助手看更早的图）、`ask_helper`（让助手联网查资料）。
- 决定是一个 JSON（`BotCore/QQAgentPlan.swift`）：`reply` / `silence` / `wait`。回复时按顺序最多 5 个“气泡”：文字（最多 3 条，可引用目标消息）、表情包（写想要的画面，由助手从表情库挑）、贴表情、戳一戳、画图。程序只认它被允许的消息编号、成员和表情，逐条发送，条间按上一条长度停 1.2–4 秒；每条都走限速、`noteSent` 和发送记录。`wait` 过几秒带着这批再看一次，新消息会提前叫醒它。
- “助手”模型（用途 `operator`）负责挑表情包、看图、查资料，可以用便宜的模型。两者都在「模型 → 模型分工」里选。
- 每一批的结果和理由记在“最近的小动作”和总览的接话判断里（“交给代理”）。代理模式的群不再单独跑“群里的小动作”，贴表情和戳人由指挥一起决定。私聊不受影响。

## 模型分工与省 tokens

「模型」页下方的“模型分工”：每种用途（`bridge/gateway.mjs` 的 `purposes`：回复起草 chat、改口吻 rewrite、插话校对 review、群聊摘要 summary、记忆整理 memory、小动作 react、画图判断 imageplan、戳一戳 poke、主动聊天 outreach、看视频 video）可以单独指定连接和模型，没指定的跟着“当前使用中”的连接。指定的连接出错或没额度时，这一次自动改用当前连接（总览的最近调用里标 `fallback`）。存在 `providers.json` 的 `routes`。

- **起草 + 改口吻**：引擎先按 `chat` 的分工把整段上下文、记忆、工具交给起草模型写出回复（含配图选择），再在“改成大肥鱼口吻”打开时，把草稿和最近约 3000 字的聊天交给改写模型（无工具、不深度思考），只改说法、不改意思（`Services.swift` 的 `rewritten`，提示词 `rewritePrompt`）。改写失败或格式不对就发草稿。是否有改写阶段由网关 `/v1/model-info` 的 `rewrite` 字段告诉引擎，30 秒刷新一次。问它“你用的什么模型”会说起草用谁、口吻由谁改。
- **群聊滚动摘要**：群时间线最后 12 行一直给原文；更早的行每滚出 10 行，就在后台用 `summary` 的分工把它们和上一份摘要合成一段不超过 500 字的前情（`BotCore/QQTimelineDigest.swift`），回复时用 `[前情摘要]` 一行代替那些原文（`QQGroupContext.context(summary:)`）。只在机器人最近半小时在这个群说过话时才做，不然只读不说的群反而多花钱；失败后五分钟再试；两小时前的旧摘要不再往下传。开记忆时摘要存盘。
- 记忆整理、摘要、改写、小动作在 Codex / Claude Code 上用低思考强度。

## 内容合规

网关给每一次面向聊天的模型调用（回复、群聊插话、校对、主动聊天）都加上一条优先于人设的规则：遵守中华人民共和国法律法规，不碰领导人和政治人物、政治制度与时政敏感事件、历史政治争议、分裂与民族宗教问题、邪教、恐怖暴力、赌毒、违法犯罪方法、谣言；不搞黄色（色情、性暗示、擦边、黄段子都不写，也不接黄腔）。遇到这类话题一句话自然岔开，不解释、不复述（`bridge/providers.mjs` 的 `withCompliance`），三种模型连接都生效。画图同样拒绝政治和任何性感、擦边内容；找插画除了 Pixiv 的 R-18 标记，也按标签跳过泳装、内衣等擦边作品（任何模式都过滤）。

## 联网搜索

- 模型是本机 Codex 或本机 Claude Code 时，搜网页、读网页、查天气直接用模型自带的官方联网搜索（Codex 的 `--search`，Claude Code 的 WebSearch），网关会把引擎提供的同类工具（`search_web`、`browse_web`、`read_webpage`、`get_weather`）替换掉，见 `bridge/providers.mjs` 的 `useNativeSearch`。Claude 只开服务端的 WebSearch，不开会从本机抓网页的 WebFetch。
- 机器人自己的工具保留：打开具体网页（`read_webpage`）、天气（open-meteo）、下载别人发来的图片和表情来识图、搜出能直接发到群里的图片、找插画、B 站视频（标题、简介、字幕和前 35 秒抽帧；BV 号、av 号、视频链接和 b23.tv 短链都行，`read_webpage` 打开 B 站视频链接也走这条路）、时间（默认北京时间）和计算。
- **本机开着 TUN 代理时**：域名会被解析成 `198.18.x.x` 的假地址，由代理按域名分流。网关只用真实地址核对“是公网”，实际仍连假地址，让代理按域名走（B 站等国内站点直连）。原来网关自己解析出真实 IP 再直连，代理认不出域名，B 站请求从日本机房节点出去，被 B 站风控返回 412。网页工具不再限定“只能打开对方发过或搜到过的链接”、不再拒绝带长数字的关键词、不再只允许 80/443 端口；唯一保留的限制是不访问本机和局域网地址。
- 提示词要求主动联网：遇到新闻、作品、人物、产品、比赛、天气或没把握的事实先查再答，查不到换关键词再查，不让对方自己去查。
- 用云端 API 时（不保证有搜索），仍走原来的工具。
- 这些都受「功能」页「联网与常用工具」开关控制。实测：两边都能查到当天天气，一次带搜索的回复约 20–25 秒（`tests/live-native-search.mjs`）。

## 去掉的过度限制（Codex 加的）

- 测试连接、保存设置、切换模型时网关拒绝聊天请求或要求先暂停回复：现在互不阻塞，正在进行的回复用开始时的配置完成。
- 原项目面板（「会话与详细设置」）里改会话范围、人设、额度、生图识图、插画、导入表情都要先暂停，保存后还停着要手动再开始；“回复字数上限”输入框写死最多 200。现在回复中直接保存，回复不停；字数上限到 2000。关掉或移除的会话，排队中的回复会自动作废。
- 切换模型必须先测试通过：改为控制台里提示一下，可直接切换。
- 云端 API 只允许 HTTPS、改地址就清空密钥：现在 HTTP/HTTPS、局域网模型服务都能填，密钥保留。
- 给 Codex 的系统指令写着“不要使用 Codex 工具”导致连搜索都不用：改为只禁止读写文件和执行命令。
- 每次调用都会报一条“开发中功能”的警告：去掉了对应的实验开关。
- 保留的安全边界：聊天模型不能执行命令、读写文件或用 MCP；网页工具不访问本机和局域网；控制台密码与来源校验；sudo 只开放固定的容器命令。

## 已知限制

- NapCat 的快速登录记录有时会失效，此时只能扫码，这一步需要你来做。
- 引擎回复速度取决于所选模型：本机 Claude Code（Opus）普通一条约 6–7 秒，需要联网搜索时 20 秒以上；本机 Codex 每次都要冷启动 `codex exec`，一条十几到二十秒。
- 云端 API 需要你自己的 Key，真实云端账号尚未实测。
- 生图、Google 以图找来源等需要额外第三方密钥的功能，没配密钥就保持关闭。
