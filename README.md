# 大肥鱼 QQ 机器人 · 本机部署

基于 [SAKURAfan1023/dafeiyu-bot](https://github.com/SAKURAfan1023/dafeiyu-bot)，上游版本 `cc8170396bc68266077204576f8469e414b5c44c`。原项目接 DeepSeek，这里换成本机模型：本机 Codex（复用 ChatGPT 登录）、本机官方 Claude Code，或自己的云端 API，在控制台里切换。QQ 引擎、人格、表情、会话记忆和原面板保留。

## 日常使用

- **启动**：双击 `Dafeiyu.exe`（或 `Start.cmd`）。它在后台拉起 WSL、Docker、NapCat 和机器人，不弹任何终端窗口，托盘里出现大肥鱼图标，然后打开控制台。
- **托盘菜单**：打开控制台、暂停/开始回复、重启机器人、重启 NapCat、开机自启、停止大肥鱼并退出、只退出托盘（机器人继续运行）。双击图标也会打开控制台。
- **开机自启**：托盘菜单或控制台「设置」里开关，写入当前用户的 `HKCU\…\Run\Dafeiyu`，默认关闭。
- **控制台**：`http://127.0.0.1:18191/console/`，只监听本机。第一次从启动器或 `Console.cmd` 打开时设置密码，之后用密码登录；密码在「设置」里随时改，改完其他浏览器需要重新登录。
- **远程打开（frp 等隧道）**：设置过密码后，用隧道的域名访问 `/console/` 也可以，必须登录；直接打开 `/bot/` 或 NapCat 页面会先跳到登录。通过隧道只能用控制台和它内嵌的页面，模型接口 `/v1/*` 和启动器令牌只认本机地址。连续输错 5 次密码锁 30 秒，再错锁定时间翻倍（最长 1 小时）。隧道是明文 HTTP 时密码和登录 Cookie 会明文过网，建议在 frp 上配 HTTPS。
- **QQ 掉线需要重新扫码时**：控制台「QQ 登录」页直接扫。扫完监督程序自动核对账号、重连，并恢复到你上次的回复状态（在回复就继续回复，暂停就保持暂停）。
- `Stop.cmd` 停止全部组件；`Status.cmd` 查看状态。

会话名单跟着 QQ 走：机器人退了群、或对方不再是好友时，会话自动从名单移除并记在总览的“已自动移除的会话”里；群和好友改名自动同步。连上 QQ 时和之后每 10 分钟核对一次；如果好友或群列表一次拿回来是空的、或者一次要删掉同类会话的一半以上，当作 QQ 那边出错，不动名单。

进群：只有管理员（「管理员与黑名单」里的 QQ）邀请时，机器人才自动接受邀请，并把这个群加进名单、直接开始回复（暂停时也照样处理）。别人的邀请不接受，留在 QQ 里由你决定；别人直接把它拉进群时（常见的是群主应管理员的要求拉的），只要有一位管理员本人就在这个群里，也加进名单并开始回复；管理员不在群里就不加，运行记录里会写是谁拉的，这个群仍会出现在联系人里，可以在会话设置里手动加。名单满 20 个时不再自动加。

接梗：群友教它“有人说 A 你就接 B”这类无害的梗，记忆整理会存成“接梗”（cue）记一年。之后群里有人说出 A，代理这一轮会看到“这批消息说中了群友教过你的接梗”，由它按约定接。别人告诉它的外号、谁是谁、怎么打招呼，也会记在说出这话的人名下，记一年。

回复里中文旁边的半角 `, ? ! : ;` 会自动改成全角；链接、数字、英文和 `:)` 这类表情不动。

所有设置都可以在回复进行中直接保存，马上生效，不用先暂停，保存后也不会停下回复；正在生成的那条回复照常发完。

## 聊天命令

代理看懂后用 `manage_chat` 去做（也可以直接用话说，比如“把他拉黑”），能不能做由程序按提要求的人核对。

| 命令 | 作用 | 谁能用 |
| --- | --- | --- |
| `/help` | 列出命令 | 所有人 |
| `/new` | 开新话题，忘掉短期上下文，长期记忆保留 | 私聊里的对方；群里仅管理员 |
| `/clear` | 新话题，并清空这个会话的长期记忆 | 私聊里的对方；群里仅管理员 |
| `/拉黑 QQ号`、群里 `/拉黑 @某人` | 拉黑后此人在私聊和群里都得不到任何回复，也不进记忆 | 管理员 |
| `/解除拉黑 QQ号` | 移出黑名单 | 管理员 |
| `/黑名单` | 查看黑名单 | 管理员 |
| `/记忆` | 列出它在这个会话里记得的关于你的事，带日期 | 所有人（只看自己的） |
| `/忘记 关键词` | 删掉关于你、带这个关键词的记忆 | 所有人（只删自己的） |
| `/model` | 回答当前用的具体模型 | 所有人 |
| `/性格` | 查看或切换本会话性格 | 查看所有人；群里切换仅管理员 |

管理员在控制台「管理员与黑名单」里填写；机器人登录的 QQ 本身也算管理员。管理员不能被拉黑。

## 2026-10-28 修复的“一直掉”

1. **引擎崩溃**：联网搜索、读网页、下载收到的图片和表情、找图、生图都经过 `upstream/Sources/WeChatAIBot/BoundedDownload.swift`。原实现每次下载新建一个 URLSession，并在它自己的完成回调里作废释放；Linux 版 Foundation 会因此报 `_MultiHandle deallocated with non-zero retain count` 并 abort（SIGABRT）。开启联网和识图后几乎每次聊天都会走到这里，所以“发句话就有概率死”。现在改为每个调用方一个长期复用、永不作废的下载 session，由统一的回调对象按任务分发，大小上限和禁止重定向的保护不变。
2. **崩溃原因被吞掉**：监督程序把引擎的标准输出和错误输出接进管道却从不读取，报错丢失，管道写满还会把引擎卡住。现在错误输出直接写入 `~/dafeiyu-gpt/engine.log`，并开启 Swift 崩溃回溯。
3. **关掉黑框整个机器人下线**：WSL 在没有 Windows 进程挂着时会自动关闭整个子系统。原来的保活进程用 `-WindowStyle Hidden` 启动，在 Windows Terminal 是默认终端时照样弹出空白窗口，关掉它 WSL 就随之关闭。现在保活进程用 `CreateNoWindow` 启动，没有窗口。
4. **掉线后不自动回来**：监督程序原来只在启动时连一次 QQ。现在 QQ 断线后会自动重连（实测 8 秒，仍核对账号，不会换号），并按你上次的选择恢复回复。NapCat/机器人重启也不再把回复改成暂停；NapCat 网页接口的凭证失效时自动重新登录。
5. **服务被杀后不重启**：两个 WSL 服务原来是 `Restart=on-failure`，而 SIGTERM 在 systemd 看来是正常退出，网关被杀后不会拉起。现在是 `Restart=always`（`scripts/install-services.sh`），只有 `systemctl stop` 才会真正停下。

## 聊天体验

- **长期聊天**：私聊读最近 40 条 QQ 记录，群聊带最近 60 条时间线（较早的压成滚动摘要）；长期记忆照常按会话整理，人设里也要求熟了之后自然接上之前聊过的事。`/new` 只清短期上下文，`/clear` 连长期记忆一起清。
- 默认额度提高到每天 1500 次模型调用、1500 条发送、单个会话 400 条（分段消息按条计）。
- **换模型、暂停、重启不再忘事**：暂停回复原来会把私聊最近几轮和群聊时间线一起清空（以前切换模型会先暂停，所以“一换模型记忆就全没了”），现在暂停只停手头的回复；私聊最近 8 轮也存进状态文件，部署重启后还在。长期记忆整理时，模型交回的条目里有不合格的只丢那一条，不再整批作废（换了格式习惯不同的模型后，整批作废会让记忆一直记不进去）；外层也宽松：代码块包着、多了字段、摘要超过 400 字、条目超过 12 条都截断接受，单条缺 `replaces`/`days` 等可选字段按默认值补。整理失败时记录和状态里写明原因。检索时除了关键词命中的，还总会带上关于当前说话人的事实、偏好、待办和最近两次聊天摘要。
- **QQ 表情看得懂**：纯 QQ 自带表情会写成“[QQ表情：捂脸]”这类名字（表从 NapCat 容器里的 QQ 导出，`scripts/export-face-names.sh` 可重新导出），只发一个表情不会被当成要回答的话题。
- **夜间安静**：默认 2:00–8:00 不主动插群聊、不贴表情；有人 @ 它、回复它、发命令照常回。「功能」页可关或改时段。
- **饭量**：有人问它吃了多少 token、花了多少钱，它会查用量账本回答（今天、近 7 天、近 30 天）。
- **找主人告状**：有人一直骂它、刷屏、找主人，或者它发现自己出了故障，可以私聊控制台里的第一个管理员说一声；一天最多 3 次，两次至少隔 10 分钟。
- **卡住时说一声**：有人跟它说话但模型限流、超时或出错，它回一句“吃撑了/卡了，等会儿再问我”，而不是一声不吭；同一个会话 10 分钟最多一次，这句不调用模型。
- **看得见群里发生了什么**：群时间线里每条消息带发言人的群名片，群主和管理员会标出来，还会写明是哪个群。精华、撤回、禁言、设管理员、进群退群这些 QQ 通知也会写成一行“[群通知]”，比如谁把谁的哪条消息设成了精华；被撤回的消息会从它看到的时间线里拿掉。没有通知记录时，它不会去猜这些事是谁做的。原来这些通知全被丢掉，它曾经把别人的消息被设精华，脑补成“你把‘唐完了’设成了精华”，还编了个“群主”。
- **说话像群友，不像解说员**：大家刚看到的事不复述、不解释后果，不拍马屁、不下总结评语；能一句话就不说两句；看岔了短短认一句改正，不长篇检讨。
- **不乱认错**：被说“你瞎编”“你唐了”时先对照上下文和图片，有依据就坚持、简单说出依据；真错了才认。
- **人设**：`personas/dafeiyu.txt`，大肥鱼本鱼——蓝发鲸鱼娘，可爱靠态度不靠语气词，偶尔自称本鱼、偶尔一个鲸鱼小动作；清楚自己能查资料、找图、画画、看视频，不会说“我只是个 AI 群友”。`scripts/apply-persona.py` 写入配置。
- **在聊天里存表情**：引用一张图（或直接发图）对它说“把这个表情存一下”，它会看一眼画面、起个名字、判断情绪和适用场合，存进表情库，之后合适时就会发。只有控制台里配置的管理员和机器人自己的号能让它存，其他人会被告知去找管理员；色情擦边、政治、血腥、真人隐私、广告二维码不存；同一张图不会重复存。存的是原图，动图（GIF）原样存、原样按动画表情发出；控制台导入 GIF 也一样（其他格式转成 PNG）。表情库每张最多 3 MB：更大的动图（最大 16 MB）先缩小画面（最长边 480→200 px）、还不够再隔帧抽掉（时长不变）压到 3 MB 以内，仍然是动图（11-01 一张 3.6 MB 的动画表情因超限被存成了第一帧）。

## 被禁言、发送失败

- 群里收到禁言通知（禁言本账号或全员禁言）就只停这一个群：照常记聊天和记忆，不回复、不贴表情、不戳回去；时间到或收到解禁通知自动恢复。运行记录里会写被禁言多久。
- QQ 明确拒绝一条消息（被禁言、被踢、风控等）记为“没发出去”，并顺手查一下是不是被禁言了；不再把它当成“发送结果未知”、更不会因此暂停整个机器人。原来一个群禁言会让所有会话都停掉。
- 真正不知道发没发出去（等回执超时、连接断了）的消息不重发，也只记一笔，不暂停。

## 被腾讯踢下线

症状：NapCat 发来 `bot_offline`（“你的账号当前登录已失效，请重新登录”），之后收不到消息、发消息报 1200 EventChecker，但心跳照常，NapCat 管理页也还显示已登录（NapCat 的已知问题），所以监督程序会把引擎重新连上一个已经失效的会话。被踢后不会自己恢复，要在「QQ 登录」用机器人的手机 QQ 重新扫码。

- 引擎记下被踢的时间（面板状态 `kickedAt`），直到重新收到任何 QQ 事件才清掉；这段时间控制台总览标红“QQ 被踢下线了”，托盘菜单显示“QQ 被踢下线，请在控制台扫码”，并弹一次 Windows 通知。连续两次发消息被 EventChecker 拒绝也会在总览报警。
- 2026-10-29 一天被踢 3 次（07:22、11:34、19:40），其中 07:22 那次之前四个小时一条消息都没发，不是发太快造成的。当时容器启动脚本设了 `NAPCAT_DISABLE_BYPASS=1`，NapCat 自带的反检测全关；NapCat 的 issue（NapNeko/NapCatQQ#1728）里有人反映 Docker 部署 2–3 小时一掉、开反检测后稳定。已去掉这个环境变量，并在 `~/qq-runtime/config/napcat.json` 和 `napcat_<QQ号>.json` 里打开 `bypass` 的 hook、window、module、process、container、js 六项（改前的文件备份在 `~/qq-runtime/backup-20261029-195200/`）。改这两个文件和 `qq-container-entrypoint.sh` 要原地写（它们是单文件挂载进容器的，`sed -i` 换了文件容器看不到），然后重启 NapCat。`o3HookMode` 保持 0（NapCat 文档对频繁掉线的建议）。
- 开反检测后两天多没掉，2026-11-01 00:42 又被踢一次。配置没被改回去（两个 napcat 配置文件六项仍开，入口脚本没有 `NAPCAT_DISABLE_BYPASS`），NapCat 是 4.18.41，最新的 4.18.42 没有掉线相关修复。那次前一小时发了 22 条，而且前后一小时里引擎被反复部署重启了六七次（每次重连都会向 NapCat 一口气拉好友和群列表），代理模式的贴表情、戳人、翻记录也比旧流程多。所以加了节奏控制（`SendUsage`）：最近十分钟发了 8 条以上，两条之间的间隔按比例拉长（最多 30 秒）；间隔设成 2 秒以上时每条再随机多等 0–2 秒，不出现固定节拍；所有会话合计每小时最多发 90 条（「记忆与额度」可改），到了就告诉代理先歇；贴表情每小时最多 20 次、戳一戳 8 次、点赞 5 次。每次被踢记下时间和被踢前一小时、十分钟各发了多少（`kicks`，存在状态里，总览“被踢记录”），以后看是不是跟发送频率有关。部署时尽量一次改完再重启，别在群里活跃时连续重启。
- 其他已知诱因（NapCat 文档）：机器人号和你自己的 QQ 在同一个 IP / 同一台电脑上登录、同一个号在别的电脑上也登录、新号。全局发送间隔（原项目面板「额度」里的“全局发送间隔”）10-29 从 1 秒调到了 3 秒，减少短时间连发。

## 主动找人聊天（默认关闭）

控制台「聊天行为」页的“主动找人聊天”。只在私聊里：和某个好友一段时间没聊（默认 24 小时），程序叫醒这个私聊的代理，告诉它多久没聊了；它翻自己的记忆和聊天，自己判断要不要发一条——比如问问之前说的考试、面试后来怎么样，或者轻松打个招呼；没有合适由头就不发，过几小时再看。

- 对方没回上一条主动消息，不会再发第二条；同一个人两次主动之间至少隔一段时间（默认 48 小时）。
- 免打扰时段不发（默认 23:00–9:00，北京时间）。可以取消勾选不想被主动找的人。
- 从没真正聊过、没有任何记忆的好友不会被主动找；需要打开「独立长期记忆」。
- 一次检查只排一位好友，消息不会同时发给所有人；回复暂停时不发。

## 贴表情

代理的 `react` 工具：QQ 自带的所有表情（`faces.json` 里的 280 多个，名字从 NapCat 容器里的 QQ 导出）和 QQ 能贴的常见 emoji 都能贴，`emoji` 写名字（“吃瓜”“捂脸”“666”“鲸鱼”）或 emoji 本身（🐳🔥），程序查到编号再贴（`QQReactionCatalog`，`BotCore/QQReactions.swift`）；写错了会告诉它相近的几个。拿不准就 `search_reactions` 按意思搜。控制台「聊天行为 → 常用表情」是主人希望它多用的几个（默认 🍭 棒棒糖、🐳 鲸鱼、❔ 问号、👊 拳头最常用），每轮开头列给它，设成“不用”的不贴。QQ 不收的编号记下来，之后不再给它。贴表情每小时最多 20 次（防风控）。表情编号可以用 `scripts/find-face-ids.sh 名字` 核对（需要能用 docker）。

## 代理模式（所有会话）

每个会话（群和私聊）都由模型自己操作 QQ，像 Tulpa 那样：看到新消息后它调用工具做事，每个动作立刻执行、结果马上回给它，它再决定下一步，直到不再调用工具。不按条数、关键词或斜杠命令的正则决定。控制台侧栏「代理模式」页能看到它每一步做了什么、为什么。11-01 起原来的固定回复流程（按条数主动接话、关键词自然接话、等对方说完、斜杠命令程序直接回、单独的“小动作”模型、被戳时固定回一句、主动聊天单独生成）整个删掉了，这些事都交给代理。

- **攒批**：会话里每条新消息都进时间线；安静 2 秒（或攒满 8 秒）就成一批，交给“指挥”模型（用途 `director`）。主人的人工发言、黑名单、被禁言、被判定为机器人互聊的不交；群里夜间安静时段只有叫到它（@、引用它、叫名字）才交。私聊每条都算叫到它。
- **提示词**：代理模式有自己的一套（11-01 重写，用户嫌旧的“有点奇怪”）：`QQPersona.agentPrompt`（`BotCore/QQAgentPrompt.swift`）只写角色、当前性格、说话长短和主人的补充偏好；`QQAgentPlan.prompt` 分节写清在做什么、怎么看聊天记录、什么时候说话、怎么做事、做事的规矩、怎么说话、底线、怎么结束。旧流程那套要求输出 JSON、讲配图情绪的人设提示词不再给代理用。
- **一轮开头它看到的**：时间和权限、这一批的消息编号、时间线（群里较早的部分是滚动摘要；私聊读 QQ 自己的历史，所以也看得到主人亲自打的字）、被引用的较早消息原文、相关记忆和接梗、它的笔记本、定好的事、它最近在这里做过的事、谁是机器人管理员；这批和被引用消息里的图片直接附像素。
- **动作（立刻执行，结果回给它）**：`send_message`（可 @、可引用）、`search_stickers` + `send_sticker`（它自己按画面搜表情库、按编号发，结果标出最近发没发过；以 QQ“动画表情”发出）、`react` 贴表情、`poke`、`like`、`recall` 撤回自己两分钟内的消息、`send_voice`、`draw_image`、`send_artwork`、`set_reminder` / `cancel_reminder`、`send_to_chat` 去名单里别的会话说一声、`check_new_messages`、`wait`（3–60 秒后看新消息）。每个动作都按原来的气泡规则核对（`QQAgentPlan.toolBubble` 转成气泡再 `decode`：只认程序给的消息编号、成员、表情、自己的消息、定时编号），再走限速、`noteSent` 和发送记录；连发几条按打字速度停顿；私聊里第一次发之前看一眼主人是不是亲自回了。发失败、没找到都照实回给它，由它补救。
- **查和记**：`search_chat_history`、`read_qq_history`（直接从 QQ 读更早的记录，只给名字和成员标签不给 QQ 号）、`look_at_image`、`member_info`、`group_info`、`ask_helper`、`browse_bilibili`、`model_info`、`find_artwork`、`remember`（当场记进长期记忆）、`write_note` / `delete_note`（它自己的笔记本，按会话或全局，每轮开头给它看，存在状态里，「代理模式」页能看到）、`save_sticker`（存原图，动图保持是动图）、`notify_owner`、`manage_chat`（新话题、清空记忆、拉黑/解除、黑名单、看/删关于某人的记忆、切换/恢复/列出性格；完全权限下按管理员要求设精华、禁言 1–60 分钟、解除禁言，机器人得是群管理员，不禁言机器人管理员）。斜杠命令在代理模式的会话里不再由程序解析，代理看懂后用 `manage_chat` 去做。
- **做事途中的新情况**：每个工具结果后面附上这期间新来的消息，以及有人戳它、给它的话贴表情、它定的事到点、后台的事做完（并从下一批里拿掉），它看到了就照常应对；它要结束时如果又来了新的，先给它看再结束；`wait` 一有新情况就提前返回。原来戳一戳这类要等前一轮整轮做完再排队（11-01 “戳一戳也要等前面的任务执行完再排队”）。有人戳它、给它的话贴表情时，会叫醒这个会话的代理，由它决定戳回去、说一句还是不理（同一个人 30 秒内只叫一次）。
- **同时做几件事**：慢活不卡住会话（11-01 “让他画图，他就会等到画图完成才接着回应”）。`draw_image`、`computer_task` 3 秒没做完、`ask_helper` 25 秒、`browse_bilibili` / `look_at_image` / `send_voice` / `find_artwork` 20 秒没做完，就转到后台接着做（`agentSettle`，秒数在 `QQEngine.agentPatience`）：工具先告诉它“转后台了”，它先回一句（“在画了”）、照常处理别的消息、结束这一轮；做完时结果送进正在跑的那一轮，没有在跑的就叫醒一轮，画好的图做完就直接发出去。还在后台的事每轮开头列出来，免得它重复去做。一次回复里同时调用的几个查询工具（看图、查资料、刷 B 站、翻记录、查成员、搜表情等）并行做；动作按顺序做。最多 8 个会话同时各跑一轮。
- **不许空口答应**：被叫去查、去看、去刷就当轮用工具做完再说结果（10-31 它曾答应“去 B 站刷完回来分你”，实际什么也没做；11-01 它说“我翻翻表情库”后表情没发出去，因为旧做法是先写好整套计划再由程序执行，它看不到执行结果——这正是改成工具循环的原因）。真要过一段时间的事（提醒、回访）用 `set_reminder`：1–1440 分钟后程序把它叫回那个会话，带着它当时写的“要做什么”再看一次聊天、自己措辞；定时存在状态文件里，重启不丢；重启后没有聊天上下文时直接发它预先写好的那句。每个会话最多 5 个，「代理模式」页的“定好的事”列出全部。
- **被叫到不许装没听见**：有人 @ 它、引用它、叫它，或者它三分钟内刚在这里说过话，而它要结束这一轮时一句话也没发（只贴表情、戳人也算没发），程序提醒它一次（`QQAgentPlan.nudge`），记录里标“提醒后出声”。11-01 用户截图：群友说“你看他都不说话”，它以“刚回过了”为由不出声。
- **权限档**（每个会话一个，`QQConfig.agentLevels`，11-01 起默认完全；`QQAgentLevel`）：基础＝只在被叫到时看，能说话和 @ 人、发表情包、贴表情、撤回自己刚发的、查群友资料；标准＝自己决定要不要插话，另加戳人、定时、发语音、联网查资料、刷 B 站、看群公告和精华、翻 QQ 记录、当场记住、记笔记；完全＝再加画图、找插画、存表情、点赞、通知主人、给别的会话发消息、按管理员要求设精华和禁言。档外的工具不给，档外的动作拒绝并告诉它。
- **人的身份**由程序核对，不靠模型自觉：`manage_chat` 必须带 `requested_by`（这一批里提要求的那条消息），拉黑/解除拉黑/看黑名单、群里清空上下文或记忆、群里改性格只认机器人管理员；看和删关于自己的记忆谁都行；存表情、设精华、禁言也只认管理员。黑名单里的人一概不理。
- **两个模型**：指挥（`director`）负责看、拿主意、说话；助手（`operator`）跑腿（查资料、看图、刷 B 站、挑表情包），可以用便宜的模型。都在「模型 → 模型分工」里选。
- **配置**：每个会话的权限档 `QQConfig.agentLevels`；网关 `/console/api/agent` 读写它并返回各会话状态（`agentStates`）和完整记录（`agentTurns`：收到什么（含途中新来的）、每一步做了什么及结果摘要、发了什么、它写给主人的理由、耗时、tokens；11-01 起和状态一起存盘，保留最近 200 批，重启时没看完的标成出错）。网关重启时，引擎的模型调用会等它约 30 秒再试；一批看失败了（任何原因）而且还什么都没发出去时，会带着这批和期间新来的消息自动重试两次（3 秒、10 秒后；已经发过东西就不重试，免得重复回），都失败才记“处理失败”并在被叫到时说一句卡了。
- **发语音**（`send_voice`，标准和完全权限）：控制台「语音」页填主人自己的 OpenAI API Key（存 `.runtime/voice.json`，只写不回显）后打开。默认走 Realtime API：`gpt-realtime-2.1-mini` 按配音员的指示把那句话原样念出来，音色默认 marin，PCM 包成 WAV 交给 NapCat 作语音发出（`bridge/voice.mjs`、`QQVoice.swift`）。旧的 `/audio/speech`（tts-1、tts-1-hd、gpt-4o-mini-tts，OpenAI 宣布 2027-01-06 停用）留作“兼容模式”给只支持它的中转用。合成或发送失败时那句话改发文字。引擎每轮问网关 `/v1/voice` 决定给不给 `voice`。
- **语音怎么发出去**：NapCat 收到不是 SILK 的音频会在容器里用 ffmpeg 转，那一步在这台机器上会失败（QQ 回 1200，11-01 “嗓子卡住了”就是这个）。所以网关自己转：Realtime 的 24 kHz PCM 直接、MP3 先用 WSL 的 ffmpeg 解码，再用 pilk 编成腾讯 SILK（`bridge/silk.py`，私有 venv 由 `scripts/setup-voice.sh` 装在 `~/.local/share/dafeiyu/voice-venv`），NapCat 拿到就直接发。但 NapCat 发之前还会用 ffprobe 读时长，同样失败——根因是容器入口脚本设了 `FFMPEG_PATH=/usr/bin/ffmpeg`：设了它 NapCat 就不用自带的 ffmpeg 原生插件，改调容器里不能用的命令行 ffmpeg/ffprobe（NapCat 源码 `ffmpeg-adapter-factory.ts`）。11-01 已从 `~/qq-runtime/qq-container-entrypoint.sh` 删掉这一行（原地改，备份 `backup-entrypoint-*.sh`），NapCat 重启后生效。在那之前，群里 OpenAI 语音发不出去时自动改用 QQ 自带 AI 语音，再不行才改发文字。群里没填 OpenAI Key 时用 QQ 自带的 AI 语音（NapCat `send_group_ai_record`，免费，只能在群里），角色在「语音」页选，默认傲娇少女（`lucy-voice-f38`）。真发不了时程序会告诉代理原因，提示词要求它照实说，不编“嗓子卡了”之类的借口。
- **超级模式（操控电脑）**：「代理模式」页打开、填主人 QQ 号后，主人在和机器人私聊时，代理多一个 `computer_task` 工具：网关在 Windows 上跑本机 Codex（`codex exec -s danger-full-access`，工作目录 `D:\Dev\Workspaces\dafeiyu-computer`，`bridge/computer.mjs`）。查看类的直接做；删改文件、装卸软件、改设置、关机重启、发消息花钱这类，Codex 先停下来说要做什么，代理转告主人，主人回了确认，代理再带着 `confirmed_by`（主人那条消息的编号）调用一次——程序核对那条确实是主人在这之后发的，不信模型自己说“确认了”。只认那一个 QQ 号，群里和别人的私聊一律没有这个工具；每次运行记在 `.runtime/computer-log.jsonl`，页面上能看到最近几次。
